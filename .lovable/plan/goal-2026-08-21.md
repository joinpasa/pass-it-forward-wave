## Goal

Fix custom pledge entry everywhere so a visitor can erase the preset and type a new value such as `73` without the field forcing `1` and producing `173`.

## Confirmed diagnosis

- The website pledge form (`/commit`, also reused by the wave/share flows) now allows the field to become empty and correctly accepts `73`.
- The standalone app join form (`/app/join`) still stores the field as a number and immediately converts an empty value to `1`; a browser reproduction confirmed the sequence `10 → 1 → 173`.
- The website and app are one React project and share the same backend, but these two pledge screens currently use separate frontend components. Therefore this specific input behavior must be corrected in the app component as well; it is not a separate deployed product or backend fix.

## Implementation

1. Update the `/app/join` pledge field to keep editable text separately from the validated numeric pledge, matching the proven website behavior.
2. Keep the field empty while the user is replacing its value; update the numeric pledge only when the text contains a valid number.
3. Normalize an empty or out-of-range value only on blur or submission, retaining the existing minimum of 1 and maximum of 1,000,000,000.
4. Keep preset buttons synchronized with both the displayed text and submitted numeric value.
5. Add focused regression coverage for the shared user behavior: clear the default, type `73`, and confirm both `/commit` and `/app/join` display and submit `73` rather than `173`.

## Validation

- Test the web pledge form and standalone app join form at mobile width.
- Confirm preset selection still works, empty values cannot be submitted, and valid custom values are preserved.
- Check the project build diagnostics after the change.
